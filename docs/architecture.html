Factory Inventory Management System

A Vue 3 single-page application backed by a Python FastAPI service that serves in-memory mock data loaded from JSON files. Built as a Claude Code workshop demo for inventory, orders, demand forecasting, and spending analytics.

The stack is intentionally minimal — three layers, no database

Vue 3 with Composition API on the front, FastAPI on the back, and JSON files on disk loaded into memory at startup. No ORM, no migrations, no auth — optimized for fast iteration in a workshop setting.

Three tiers, one process per side, zero persistence

The browser talks to a single FastAPI process over HTTP. FastAPI reads JSON files into memory once at startup; mutations within a session are never written back to disk.

A typical request flows through six checkpoints

Walking through what happens when the user changes a filter on the Dashboard view.

1

User changes a filter in FilterBar.vue

Filter state lives in a shared composable so every view sees the same selection. Selecting "Q3-2025" updates a ref, which triggers a watcher in the active view.

2

The view calls a method on api.js

Each view loads its own data — for example, Dashboard.vue calls api.getDashboardSummary(filters). The client serializes filters into URL query params, skipping any value of 'all'.

3

Axios issues an HTTP GET to localhost:8001

FastAPI's CORS middleware accepts the request. The route handler receives query params as typed Python Optional[str] arguments.

4

FastAPI filters the in-memory list

apply_filters() walks the relevant Python list (inventory_items, orders, …), short-circuiting any filter set to 'all'. Month filters also resolve quarter codes via QUARTER_MAP.

5

Pydantic validates and serializes the response

The response_model on each route forces the output to match the declared shape — List[InventoryItem], List[Order], and so on. Mismatches raise 500s in dev.

6

The view assigns the response to a ref

Vue's reactivity propagates: computed properties recalculate, the template re-renders, charts redraw. Loading and error states are guarded by local refs in each view.

No POST, PATCH, or DELETE endpoints exist on the server today. The api.js client defines write methods for tasks and purchase orders, but those routes are not implemented in main.py.

Four filters drive every view

Filter values are exchanged as query strings. The convention is that 'all' means "no filter" — the client omits it and the server skips that comparison.

Filter parameters

warehouse category status month

month accepts both YYYY-MM and quarter codes (Q1-2025…Q4-2025) — the server expands quarters via a QUARTER_MAP lookup.

Endpoint coverage

Inventory has no time dimension, so it accepts warehouse and category only. Orders and the dashboard summary accept all four. Demand, backlog, and spending endpoints accept none — they always return the full dataset.

Code structure follows the runtime split

Each side is small and flat — no layers of abstraction beyond what the framework provides.
